# 豆包每日自动领取积分（Windows）

每天 **07:10** 自动激活/启动豆包客户端，先尝试点掉当日首次登录弹出的签到入口，再打开「免费用豆包工作」额度页核对状态，整个过程写入日志并截图。

## 文件

| 文件 | 作用 |
| --- | --- |
| `doubao_daily_claim.ps1` | 主脚本（PowerShell + Windows UI Automation，无第三方依赖） |
| `install-scheduled-task.ps1` | 重建计划任务（重装系统/换机器后跑一次） |
| `restore-encoding.ps1` | 给 ps1 补 UTF-8 BOM（刚下载下来时必跑一次，详见下文） |
| `logs\` | 运行日志与截图（本地生成，不提交仓库） |

## 部署 / 重装后恢复

1. 把仓库拉到本地，放到一个固定目录（建议非系统盘，例如 `D:\Tools\doubao-daily-claim`）；
2. **先跑 `restore-encoding.ps1`**（见下一节，不跑会出中文乱码）；
3. 右键 `install-scheduled-task.ps1` →「使用 PowerShell 运行」；
4. 登录豆包客户端，确认任务计划程序里已有「豆包每日自动领取积分」，触发时间 07:10。

## 为什么必须先补 BOM

Windows 自带的 PowerShell 5.1 读取无 BOM 的 UTF-8 文件时按 GBK 解码，脚本里的中文（包括控件名 `免费用豆包工作`、日志文案）会全变乱码，脚本直接跑不通。而 git/GitHub 存的是无 BOM 版本，因此下载后必须补回 BOM。

`restore-encoding.ps1` 会扫描同目录所有 `*.ps1`，无 BOM 的自动补上（已在 Windows 10/11 的 5.1 上实测：修完与原件逐字节一致，语法 0 错）。也可以不用它，改用 VS Code 打开后“另存为 → UTF-8 with BOM”。

## 运行前提

- 07:10 时电脑开机且已登录桌面（笔记本需接通电源）；
- 豆包客户端已登录账号；
- 脚本会自动把客户端窗口 Move 到 (158,162)、1200×800，保证点击位置固定。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 点到签到入口，或已点击签到按钮 |
| 2 | 额度页没有可点的签到控件（当前 PC 版本的常态，已记录并关标签页） |
| 1 | 客户端未启动 / 菜单未打开 / 额度页未打开 |

## 实测结论（2026-11-20，豆包 PC 客户端当前版）

- 额度页「签到领额度，每周一翻倍」只是说明卡：区域内只有文字节点，没有 Button/MenuItem/Hyperlink；点卡片文字、中部、右侧均无反应（页面控件快照前后一致）。
- 页面可点的只有：累计额度卡片、额外领 200/500/1300 额度（做任务）、团队版试用「立即领」、任务后的「去完成」。
- 因此电脑端目前点不到“每日签到”；能自动到账的是 **每日免费积分**，规则为当日首次在移动端/PC 端登录豆包时自动发放，当日 24:00 清零。

## 强制触发“当日首次登录”

客户端整夜不关就没有新的首次登录。把脚本顶部开关改为 `$true`：

```powershell
$RestartClient = $true
```

每天 07:10 会先关掉豆包再重开，从而触发首次登录。默认 `$false`，不改动你正在用的客户端。

## 环境依赖

- Win10/11 自带 PowerShell 5.1 与 .NET Framework 的 UI Automation，**不用装任何东西**；
- 计划任务由系统管理，重装必丢；脚本文件只要不在 C 盘用户目录就还在。

## 停用

任务计划程序里删除「豆包每日自动领取积分」即可，脚本不会改动任何系统设置。
